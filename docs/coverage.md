# Cypher coverage

This is a living inventory of Crabnet's observable Cypher behavior. It describes the
current implementation, not the full parser AST and not a promise of openCypher
conformance. The project is still experimental: databases may be recreated when the
schema changes, and there is deliberately no schema-migration compatibility policy yet.

## Status vocabulary

- **Covered** — implemented and exercised by an end-to-end regression test.
- **Needs test** — an implementation path exists, but its contract lacks a direct,
  focused regression test.
- **Partial** — a useful subset is covered; the omitted forms are named explicitly.
- **Rejected** — accepted by the parser but intentionally fails during planning with a
  structured `Unsupported` or `Semantic` error instead of producing a guessed result.
- **Planned** — roadmap work with no active implementation claim. Planned cases belong
  here until work begins; they should not accumulate as ignored tests.

## Query forms and patterns

| Feature | Status | Current contract / evidence |
| --- | --- | --- |
| Standalone `RETURN` | Covered | Typed literals, collections, maps, and named parameters in `return_without_match_supports_typed_values_and_parameters` |
| `MATCH ... RETURN` | Covered | Scalar and whole-entity results throughout `engine.rs`, `read_semantics.rs`, and `entity_values.rs` |
| Consecutive read-only `MATCH` clauses | Covered | Multiple `MATCH` stages compose in one read pipeline and preserve their Cartesian row semantics in `consecutive_match_clauses_use_the_composable_read_pipeline` |
| `CREATE` with optional `RETURN` | Covered | Typed nodes and directed relationships, including whole created-entity results in `create_return_uses_the_same_whole_entity_values`. Consecutive `CREATE` clauses accumulate in one transaction and later clauses reuse variables bound earlier, covered in `consecutive_create_clauses_share_bindings_and_follow_multiple_matches` in `write_semantics.rs`; the TCK `CREATE` clause-sequence setup bucket is empty |
| `MATCH ... CREATE` with optional `RETURN` | Covered | Executes once per materialized input row, reuses bindings, handles no-match, and is atomic; whole matched and created entities also cross the Rust execution stage in `match_create_carries_matched_and_created_entities_through_rust_execution`. Several `MATCH` clauses may precede the `CREATE` clauses; `MATCH` after a `CREATE` is rejected |
| `MATCH ... SET` / `REMOVE` with optional `RETURN` | Partial | Direct node/relationship properties and whole-map replacement/merge are covered in `matched_mutations.rs`. Computed right-hand sides (`SET a.x = a.y + 1`, `SET a += {k: b.v}`, `SET a = b`, computed `CREATE` properties) evaluate per row through the materialized-rows read and are covered in `computed_set_values_are_evaluated_per_row` and `write_semantics.rs`; `CREATE` may precede `SET`/`REMOVE`/`DELETE`, and `WITH`/`UNWIND`/`MATCH` may sit between them (`write_pipelines.rs`). Label mutations are covered in `labels.rs` |
| `MATCH ... DELETE` / `DETACH DELETE` with optional `RETURN` | Covered | Node and relationship targets, stable snapshots, input-bag deduplication, detach behavior, counters, and rollback are covered in `delete_mutations.rs`. Eleven tests in `delete_expressions.rs` add indexed/nested/dynamic targets, mixed node/relationship selections, slices/comprehensions/concatenation, nulls, parameters, pre-delete evaluation, mutation refresh, forged-record isolation, error/constraint/transaction rollback, and result budgets. Six additional TCK scenarios pass |
| Node scan, multiple labels, inline property map | Covered | Includes missing/null values and typed list/map equality (`missing_and_null_properties_follow_null_semantics`, `inline_structured_properties_keep_json_types`) |
| Fixed-length relationship patterns | Covered | Outgoing, incoming, undirected, self-loop, and three-hop patterns, including parallel-path multiplicity; see `creates_and_matches_a_directed_relationship`, `undirected_matches_check_both_orientations_without_duplicating_self_loops`, and `parallel_three_hop_paths_preserve_row_multiplicity` |
| Typed and untyped relationship scans | Covered | Multiple runtime types retain their own `type(r)` values in `untyped_relationship_matches_retain_each_runtime_type` |
| Relationship inline properties | Covered | `relationship_property_matching_preserves_scalar_and_nested_json_types` exercises fixed and Rust-backed open traversal filters across booleans, compatible integer/float values, strings, nested lists/maps, mismatches, and null. Bounded per-hop behavior remains covered by `relationship_and_endpoint_properties_apply_to_every_candidate_path` |
| Element-local `WHERE` | Partial | Node- and relationship-local predicates execute in `element_local_where_filters_nodes_and_relationships`. `open-cypher 0.2.1` still rejects a labeled node after an earlier node-local `WHERE` in the same pattern or clause, even with an escaped label; a separate `MATCH` clause works. Bare contextual-keyword labels can also cause later node labels to be misclassified; escaping the keyword label works. Both parser limitations await an upstream fix |
| Comma-separated patterns / bag multiplicity | Covered | Disconnected Cartesian products and repeated node bindings in `disconnected_patterns_preserve_cartesian_multiplicity` and `repeated_node_variables_reuse_the_same_binding` |
| Relationship uniqueness within one `MATCH` | Covered | Fixed and variable-length positions track edge IDs rather than nodes. One relationship cannot be reused across any constituent path pattern in the same `MATCH`; a later `MATCH` starts a new uniqueness scope. See `one_relationship_cannot_fill_two_positions_in_a_path`, `fixed_and_quantified_segments_cannot_reuse_the_same_relationship`, and `relationship_uniqueness_spans_one_match_but_not_separate_match_clauses` |
| Multiple labels/types and boolean label expressions | Partial | Nodes store a label list; `:A:B`/`&` conjunctions, `\|`, `!`, and parentheses in `MATCH` patterns, `n:Label` predicates in `WHERE` (null for null nodes), and `r:T\|U` relationship-type predicates are covered in `labels.rs`. Relationship-type alternatives inside patterns and the label wildcard `%` remain rejected |
| Legacy variable-length relationships | Covered | Mandatory read-only `MATCH` supports `*`, `*n`, `*min..max`, `*min..`, `*..max`, and `*..` in outgoing, incoming, and undirected directions. Explicit maxima through 32 use recursive SQLite CTEs; larger or omitted maxima use Rust trail enumeration materialized as JSON for SQLite. Bare/open-star minima, deep ranges, path/list values, identity, reversed ranges, filters, cycles, self-loops, diamonds, parallel edges, composition, and bag multiplicity are covered in `bounded_traversal.rs`, `path_values.rs`, `relationship_list_values.rs`, and `unbounded_traversal.rs` |
| Legacy shortest-path factors | Partial | Pattern-position `shortestPath` and `allShortestPaths` support one variable-length relationship with lower bound zero or one. Rust BFS selects one deterministic but unspecified minimum-hop trail or all ties per endpoint pair after direction, bounds, type, edge-property, parameter, and endpoint filters. Paths, relationship lists, path functions, prior bags, `WITH`, and `UNION` compose. Modern selectors, expression-position calls, optional/same-clause-`WHERE`/multi-part forms, lower bounds above one, and writes are rejected; see `shortest_paths.rs` |
| Same-endpoint shortest selection | Covered | Lower bound zero selects identity; lower bound one selects shortest positive relationship-unique cycles, with one deterministic but unspecified tie or all ties. See `lower_bound_one_finds_shortest_positive_cycles_to_same_endpoint`, `undirected_triangle_cycles_are_selected_per_relationship_sequence`, and `explicit_zero_lower_bound_selects_the_identity_path` |
| Named path bindings and values | Partial | Mandatory read-only fixed, variable-length, and mixed patterns—including deep and open-ended forms—may bind and return `CypherValue::Path(PathValue)`. Traversal order, zero-hop values, reverse stored direction, path functions, direct/computed `WITH` aliases, `RETURN DISTINCT`, and `UNION` are covered in `path_values.rs` and `unbounded_traversal.rs`. Raw path property/scalar/order use, optional-bound paths, selectors, and writes fed by a named path are rejected |
| Legacy relationship-list pattern bindings | Partial | A fresh `[rels:TYPE*min..]` binding in mandatory read-only `MATCH` returns a typed relationship list in traversal order, including deep/open-ended forms and `[]` at zero hops while hydrated relationships retain stored-direction endpoints. Direct `RETURN`, `WITH` aliases, semantic distinctness/pagination, unions, parallel-edge identity, and named-path coexistence are covered in `relationship_list_values.rs` and `unbounded_traversal.rs`. A bound list reused in a later variable-length pattern matches that exact sequence: same-clause re-matching without a uniqueness conflict, SQLite-recursive and Rust-backed forms after `WITH`, direction/bound/type mismatches, multi-segment `relationships(path)` aliases, and shortest-path forms are covered in `same_clause_rematch_denotes_the_same_relationships_without_a_uniqueness_conflict`, `prebound_relationship_lists_match_exactly_after_with`, and `prebound_lists_from_path_functions_and_shortest_forms_match_as_one_sequence`. Expansion through `UNWIND` is covered in `path_unwind.rs`. Optional bindings, writes, and general scalar/order contexts are rejected; direct count/collect and grouping are covered in `path_aggregation.rs` |
| Other variable-length and path forms | Rejected | Postfix graph quantifiers, modern path selectors, expression-position shortest-path calls, quantified `OPTIONAL MATCH`, and traversal-fed writes are not executable; supported parser forms fail during planning |
| `OPTIONAL MATCH` | Covered | Fixed-length optional patterns null-extend the complete introduced pattern, preserve outer rows and bag multiplicity, and keep optional `WHERE` predicates in the join condition; writes after it run once per row and skip null targets; see `optional_match.rs`. Quantified optional patterns, match modes, and hints remain rejected |
| `WITH` pipelines | Partial | Standalone and chained `WITH`, entity/path/scalar aliases, scope loss, `WHERE`, intermediate ordering/pagination, aggregation, `WITH *`, and later `MATCH`/`UNWIND`/`OPTIONAL MATCH` stages are covered. `WITH ALL` is accepted. Paths may cross directly or feed aliased `length`, `nodes`, and `relationships` projections; path-derived relationship-list bindings and graph lists may be carried onward and expanded with `UNWIND` (`path_unwind.rs`). Collected entity lists retain their element kind through aliases and wildcards and can feed `UNWIND` (`collect.rs`). Updating clauses may appear anywhere in the pipeline (see the row below). `WITH DISTINCT` supports typed row deduplication before pagination and later clauses, including writes; see `with_distinct.rs` for recursive values, nulls, complete rows, wildcards, graph identity, hybrid traversal, modifier scope, stable projected values, and rollback. Unaliased computed expressions remain rejected |
| `UNWIND` | Covered | Literal, parameter, property, and prior-aggregate lists expand with bag semantics; null, empty, and non-list runtime values produce no rows. Path-function and legacy relationship lists expand into entity bindings: `path_unwind.rs` covers segment junctions, cycles, self-loops, zero hops, parallel edges, stored direction, aliases, all supported path producers, later reads/matches/collection, distinctness/pagination, unions, hydration, and retained write rejections. Collected nodes and relationships expand into entity bindings usable in later matches and mutations, with identity, duplicates, empty inputs, scope, grouping, hybrid reads, and rollback covered in `collect.rs`. Scalar scope and composition cases are covered in `unwind.rs` |
| `UNION`, `UNION DISTINCT`, `UNION ALL` | Covered | Read-only branches are independently planned and must return the same column names in the same positions. Pending typed cells use recursive row equivalence, including ordered path and graph-list identity; `ALL` preserves duplicates and mixed operators apply left-to-right before shared hydration. See `union.rs`, `path_values.rs`, and `relationship_list_values.rs` |

## Writes and execution guarantees

| Feature | Status | Current contract / evidence |
| --- | --- | --- |
| Create nodes and directed relationships | Covered | Multi-element patterns, left arrows, self-relationships, fresh/reused variables, typed properties, and parameter maps. A relationship type that decodes to the empty string fails before execution |
| Matched writes use a stable input | Covered | Input rows are materialized before mutation (`match_input_is_materialized_before_create_runs`) |
| Atomic validation and rollback | Covered | Missing parameters, invalid values, invalid reuse, duplicate decoded columns/keys, empty relationship types, recursive values beyond 100 containers, and late row failures leave no partial mutations |
| Mutation summaries | Covered | Created, changed-property, label, and deleted node/relationship counts are asserted. `properties_set` counts observable top-level stored-map changes; deletion counters count actual stored rows removed |
| Mutations without `RETURN` | Covered | Empty columns/rows and exact summaries are asserted in `mutations_without_return_have_empty_rows_and_accurate_summaries` |
| Duplicate `CREATE` property keys | Covered | Planning fails before any mutation in `create_duplicate_property_keys_fail_before_any_mutation` |
| Direct property `SET` / `REMOVE` | Covered | `entity.key` targets work for matched nodes and relationships. Direct `SET ... = null`, `REMOVE`, and null entries in `+=` remove keys; unchanged assignments and absent removals contribute zero to `properties_set` |
| Whole-map `SET =` / `+=` | Covered | Literal, named-parameter, and computed maps (including another entity's properties via `SET a = b`) replace or shallow-merge properties; a computed non-map is a semantic error. Whole-map replacement retains explicit null as a Crabnet extension |
| `DELETE` | Covered | Node and relationship variables and computed targets are validated and deduplicated across the input bag. Explicit relationships are removed before nodes; deleting a still-connected node fails and rolls back the statement. `DELETE` is currently the final mutation clause before optional `RETURN` |
| `DETACH DELETE` | Covered | Incident incoming, outgoing, and self-loop relationships are deleted before nodes, with shared and explicitly targeted edges counted only once |
| Post-delete `RETURN` | Covered | Rows retain input-bag multiplicity and project materialized pre-delete entity/property snapshots even though each storage target is deleted once |
| Label `SET` / `REMOVE` | Covered | `SET n:A:B` adds missing labels and `REMOVE n:A` removes present ones, counting changed node/label pairs in `labels_added`/`labels_removed`; repeats, null targets, relationship targets, boolean label expressions, `MERGE` actions, and row refresh are covered in `labels.rs` and `matched_mutations.rs` |
| `MERGE` and `ON CREATE` / `ON MATCH` | Covered | Whole-pattern match-or-create per input row through the materialized-rows matcher: create-then-match across statements and across rows of one statement, label and property matching, computed and null pattern values, relationship merges between bound nodes in each direction and undirected, multi-match row expansion, chained merges binding later clauses, `ON CREATE`/`ON MATCH` actions, and the already-bound, missing-type, variable-length, and path-binding rejections are covered in `merge.rs`, and `MERGE` after `UNWIND`/`WITH` in `write_pipelines.rs`; the TCK `MERGE` bucket is empty apart from label mutation and path-binding forms |
